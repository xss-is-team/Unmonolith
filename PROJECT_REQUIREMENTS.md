# Требования к поддержке целого Java-проекта

**Статус:** будущее направление; сейчас приложение принимает один `.java` файл. Проверки ниже ещё не реализованы.

## Что должен уметь продукт

1. Импортировать Maven/Gradle-проект целиком, сохраняя структуру каталогов, build-файлы и исходные тесты.
2. При открытии любого файла учитывать контекст проекта: source roots, версию Java, модули, classpath и зависимости из build-конфигурации. Импорты и типы из соседних файлов должны разрешаться так же, как при обычной сборке проекта. Если контекст восстановить нельзя — показать конкретную диагностику, не выдавать неполный разбор за полный.
3. Давать архитектору граф зависимостей проекта (пакеты/классы) и CFG метода как разные представления. Из выбранного графа можно подготовить декомпозицию или рефакторинг с явным diff затронутых файлов.
4. Применять изменение к рабочей копии проекта, генерировать согласованные Java-файлы и запускать исходную сборку проекта. Исходный корпус остаётся нетронутым; изменение можно отменить.
5. Запускать существующие тесты проекта после пересборки и показывать результат по командам/сценариям. Успешные тесты подтверждают только проверенные сценарии, не математическую эквивалентность программы.

## Проверка на Apache Commons Math

`legacy/commons-math-3.6.1/` — реальный крупный Maven-проект для повторяемой интеграционной проверки, а не пример для показа пользователю.

Приёмка поддержки целого проекта должна проверить:

- импорт проекта целиком с сохранением `pom.xml`, модулей и расположения исходников;
- разбор выбранного файла с разрешением ссылок на классы проекта и библиотек через Maven classpath;
- граф зависимостей, позволяющий выбрать небольшой компонент для декомпозиции;
- preview/diff изменений по всем затронутым файлам и отсутствие изменений в исходном корпусе;
- сборку и выбранные тесты на рабочей копии после изменения;
- явный отчёт о неполном анализе, если версия Java, зависимости или конструкция не поддерживаются.

Не требуется с первого раза полностью разобрать все классы Commons Math или автоматически превратить проект в микросервисы. Сначала нужно надёжно пройти один выбранный компонент от импорта до сборки и тестов, затем расширять покрытие.
