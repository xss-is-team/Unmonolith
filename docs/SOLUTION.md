# Java Blueprints — описание решения

Веб-инструмент для кейса Axenix «Визуальная среда программирования»: Java-монолит → визуальная модель
(CFG метода и граф проекта) → диагностика Big O → правка → регенерация Java → запуск и сравнение поведения
baseline и candidate в изолированном Docker-раннере. Статусы и доказательства — в `docs/CASE_COMPLIANCE.md`.

## Архитектура

| Компонент | Роль |
|---|---|
| `apps/api` (Rust/Axum) | Гостевые сессии, проекты (один `.java` или ZIP), ревизии с оптимистичной блокировкой, оркестрация анализа (+SSE), правки, verify, benchmark. Java не разбирает: запускает JAR парсера и контейнер раннера. |
| `apps/parser` (Java 21, Eclipse JDT) | AST с разрешёнными типами, диагностика, CFG по методам, Big O и findings, граф проекта, правки через ASTRewrite (`replace_condition`, `move_statement`, оптимизация lookup-цикла в Map). |
| `apps/runner` (Docker, JDK 21) | Компиляция и запуск ревизий; контейнер на каждый вызов, без сети, read-only FS, лимиты CPU/памяти/процессов. |
| `apps/web` (Next.js 16) | Редактор CodeMirror, CFG и граф проекта (React Flow), diff ревизий, панель проверки. |

Поток данных: загрузка → JSON парсера по ревизии → просмотр → правка → новая проверенная ревизия → verify.
Границы: Rust не парсит Java, JDT не исполняет код, загруженный Java выполняется только в раннере. Если нет JAR
парсера — `analyzer_unavailable`, если нет образа — `runner_unavailable`; результаты не выдумываются.

## Поддерживаемый Java-scope

JDT разбирает весь синтаксис Java 8–21 (уровень задаётся проектом). Обязательные разделы слайда 7 (язык и
`java.lang`, консольный ввод-вывод, коллекции `java.util`, исключения) покрыты эталонными монолитами и тестами
(`AcceptanceTest`, `LegacyJavaCompatibilityTest`, e2e) и формальным чек-листом `JavaScopeChecklistTest` (по тесту на каждый пункт
слайда 7: фрагмент компилируется, разбирается без ошибок, получает CFG и анализ, содержит названные конструкции и типы).
Бонус слайда 8 (record, enum, дженерики, лямбды, Stream) разбирается и компилируется; методы внутри анонимных классов и тел констант
enum не получают CFG и анализа (парсер сообщает об этом информационной диагностикой `unanalyzed_anonymous_body`), лямбды и стримы хранятся как текст выражения. Вне рамок кейса:
многопоточность, рефлексия, файлы, сеть, `java.time`. Технический документ кейса с полным перечнем конструкций
в репозитории отсутствует.

## Диагностика Big O

`ComplexityAnalyzer` строит статическую оценку по модели стоимости (мономы по размерам коллекций) для метода и
фрагментов, с `confidence`, `assumptions` и `limitations`. Если модели для вызова нет, результат `unknown`.
Findings (`repeated_collection_scan`, `nested_collection_iteration`) содержат строку, узлы CFG, объяснение и
рекомендацию. Оптимизации предлагаются с предусловиями и обязательным подтверждением допущений: замена вложенного
поиска индексом в `HashMap` и замена `s += x` / `s = s + x` в цикле на `StringBuilder` (строка не читается в цикле, нет
`try` с `catch` вокруг, операнд не `char[]`). Ожидаемый эффект выражается статически (`method_before/after`) или замером
`POST /benchmark`. Интерфейс показывает обзор сложности проекта: сколько методов в каждом классе и самые тяжёлые методы.

## Сохранение поведения (quality gate)

`POST /verify` компилирует обе ревизии и запускает их на одинаковых stdin-сценариях; сравниваются stdout, stderr,
код возврата, таймаут и переполнение вывода (побайтово). Отчёт сохраняется. Зелёный результат относится только к
заданным сценариям и не доказывает эквивалентность на всех входах; сценарии должны достигать изменённого кода.
Параметр `repeats` (1–5) запускает каждый сценарий несколько раз: если версия расходится сама с собой (время, случайные
числа), статус `unstable`, а не ложное «поведение изменилось». Сценарий может содержать ожидаемые stdout, stderr и код
выхода. Отчёт перечисляет, чего проверка не показывает (`not_covered`), и предупреждает, если сценарии не доходят до
изменённого кода (`warnings`).

## Ограничения

- Операции правки: `replace_condition`, `move_statement`, оптимизация lookup-цикла, декомпозиция, откат. Нет добавления,
  удаления и перетаскивания блоков и извлечения метода.
- Декомпозиция (слайд 6, «при необходимости») механическая: статические вложенные типы верхнеуровневого класса выносятся
  в отдельные файлы того же пакета (`Main.java` 799 → 224 строки + 16 файлов на демо-монолите), а не распознаются по смыслу как
  Parser/Analyzer/Optimizer. Типы, которые используют приватные члены или члены внешнего класса по простому имени, не выносятся
  (причина в ответе). После декомпозиции проект становится многофайловым; старые ревизии остаются доступными для сравнения.
- Второй режим декомпозиции для монолита, где всё лежит в одном классе: группы статических методов по первому слову имени
  (`parse*` → `Parsing`, `format*` → `Formatting`, `calc*` → `Calculations`) переезжают в новый класс вместе с приватными
  хелперами и константами, которыми пользуется только группа; вызовы (в том числе из других файлов и `Host::m`)
  переписываются. Группа не выносится, если ей нужно приватное состояние, общее с остальным классом.
- В веб-интерфейсе нет экрана отката и перетаскивания блоков; остальное (оптимизации, benchmark, ZIP, export, `move_statement`, разбор монолита, проверка с повторами) подключено.
- Большая часть методов с вызовами неописанного кода получает `unknown`; тела анонимных классов и констант enum не анализируются.
- Раннер — не формальная песочница; для недоверенного трафика нужен выделенный хост.
- Недетерминированный вывод (время, случайные числа) даёт ложные расхождения в verify.

## Запуск и проверка

См. `README.md` и `./dev`. Основные команды: `./dev parser-build`, `./dev runner-build`, `./dev up`,
`./dev api-test`, `./dev api-e2e`, `./dev api-e2e-docker`; подробности и переменные — `docs/E2E_TESTS.md`.

Скриптованный сквозной прогон на демо-монолите (загрузка → диагноз → оптимизация → verify → benchmark): `./dev demo`
(`scripts/demo.py`). Реальные ответы и сводка сохраняются в `docs/evidence/demo/` (`SUMMARY.md`, `run.json`, `01`–`08` JSON);
при отсутствии JAR, Docker или образа раннера скрипт останавливается и ничего не пишет.
