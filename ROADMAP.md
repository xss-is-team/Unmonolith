- [x] Подчёркивания через `Decoration.mark` и tooltip при наведении.
- [x] Маркеры различают `error` / `warning` / `info`.
- [x] **Overview ruler** — вертикальная полоса справа от скроллбара с отметками по severity; клик прокручивает редактор к строке.
- [x] CFG-узел → выделение диапазона в редакторе; выделение в редакторе → подсветка узла в CFG.
- [x] Decorations строятся только для видимого диапазона (`visibleRanges`).
- [x] Проверен файл на 100 001 строку.

### B — CFG-визуализация — DONE

- [x] ELK (`elkjs`) основной layout; Dagre — fallback при ошибке ELK.
- [x] Back edges циклов визуально выделены.
- [x] Minimap показывается при ≥ 24 узлах.
- [x] Switch и exception/finally рёбра представлены в графе.
- [x] Клик по условному узлу сразу подсвечивает путь «Да»; повторный клик переключает «Да» / «Нет». Подсветка анимируется и остаётся видимой вместе с CFG.
- [x] При смене метода старый граф уходит (fade/slide out), новый въезжает; `prefers-reduced-motion` отключает переходы.

### C — Анализ после редактирования — IN PROGRESS

- [x] Автосохранение через 500 мс после последнего изменения.
- [x] После сохранения — повторный анализ через 700 мс с защитой от конфликтов ревизий.
- [x] API отдаёт SSE-события `started`, `progress`, `completed` / `failed`; UI показывает текущую фазу.
- [x] История ревизий и diff исходника между ревизиями.
- [ ] **Инкрементальный пересчёт** — parser сейчас повторно анализирует всю сохранённую ревизию целиком.
- [ ] **Стриминг частичных результатов** — методы и диагностики появляются по мере парсинга; сейчас parser отдаёт полный JSON в конце.
- [ ] **Убрать кнопку «Запустить анализ»** из основного потока — первый и повторный запуск должны идти автоматически; кнопка нужна только как явный override при ошибке.

## Слой 2 — Семантика и model

### D — Типы и семантика внутри одного файла — TODO

Сейчас parser выдаёт AST и CFG, но не разрешает типы и не строит data-flow.

- [ ] Разрешение типов в рамках одного файла: тип переменной, тип возвращаемого значения метода, тип поля.
- [ ] **Use-def цепочки** — для каждой переменной: где определена, где используется, где переопределяется.
- [ ] **Reaching definitions** внутри метода — основа для анализа мертвого кода и инициализации.
- [ ] **Liveness analysis** — показать неиспользуемые переменные как диагностику `unused_variable`.
- [ ] В CFG-узле показывать вычисленный тип выражения в tooltip.
- [ ] Приёмка: файл из `legacy/commons-math-3.6.1/` с обычными generic-типами разбирается без `partial`-статуса.

### E — Complexity и метрики — DONE

- [x] **Cyclomatic complexity (CCN)** по AST: базовое значение 1 плюс точки ветвления JavaNCSS; выводится для каждого метода.
- [x] **Cognitive complexity** по правилам Sonar: структурные точки, вложенность и серии `&&` / `||`.
- [x] **Глубина вложенности** (max nesting depth) передаётся для каждого метода.
- [x] Диагностики `high_complexity` при CC > 10 и `very_high_complexity` при CC > 20.
- [x] CFG подсвечивает узлы с вкладом в структурную сложность. Это не runtime hot paths.
- [x] Приёмка: тестовые значения Commons Math сверены с JavaNCSS 33.54; cognitive complexity покрыта эталоном Sonar и сценариями вложенности.

JavaNCSS расхождение: `Pair.equals(Object)` даёт CCN 8 в JavaNCSS и 6 по AST; лишние два пункта совпадают с `?` wildcard в `Pair<?, ?>`. Счётчик по AST не принимает эти типы за тернарные выражения.

Определения: [JavaNCSS CCN](https://javancss.github.io/specification.html), [Sonar Cognitive Complexity](https://github.com/SonarSource/sonar-java/blob/master/java-frontend/src/main/java/org/sonar/java/ast/visitors/CognitiveComplexityVisitor.java). Метрики ограничены телом одного метода; вложенные локальные и анонимные классы исключаются из метрик внешнего метода.

### F — Рефакторинг с diff — TODO

Сейчас редактор позволяет менять исходник напрямую. Нужен управляемый рефакторинг через модель.

- [ ] **Extract method** — выделить выбранный диапазон исходника в отдельный метод с корректными параметрами/возвращаемым типом.
- [ ] **Rename** — переименовать переменную/метод с обновлением всех точек использования в файле.
- [ ] **Inline variable** — заменить переменную её инициализирующим выражением.
- [ ] Для каждого рефакторинга: показывать unified diff перед применением; применять только после подтверждения.
- [ ] После применения: автосохранение → повторный анализ → проверить, что диагностика `high_complexity` исчезла.
- [ ] Приёмка: Extract method на методе из Commons Math, Java-файл компилируется `javac` без ошибок.

## Слой 3 — Целый проект (следующий уровень продукта)

Критерии приёмки полностью описаны в [`PROJECT_REQUIREMENTS.md`](PROJECT_REQUIREMENTS.md). Ниже — декомпозиция на технические задачи.

### G — Импорт Maven/Gradle-проекта — TODO

- [ ] API принимает ZIP-архив или путь к каталогу с `pom.xml` / `build.gradle`.
- [ ] Сохраняет структуру каталогов: source roots, build-файл, тесты.
- [ ] Определяет версию Java из `pom.xml` / `build.gradle`; если не поддерживается — сообщает явно.
- [ ] Список всех `.java`-файлов с путями, доступен в UI как дерево проекта.
- [ ] Приёмка: `legacy/commons-math-3.6.1/` импортируется без потери файлов и структуры.

### H — Dependency-aware анализ файла — TODO

Сейчас classpath при анализе — только JDK. Типы из соседних файлов не разрешаются.

- [ ] При анализе файла передавать parser'у classpath: JDK + Maven/Gradle-зависимости из локального кеша.
- [ ] Parser разрешает импорты из classpath; неразрешимые — явная диагностика `unresolved_import`.
- [ ] Если контекст восстановить нельзя — статус `partial` с конкретной причиной, не молчаливый partial.
- [ ] Приёмка: файл из Commons Math с `import org.apache.commons.math3.*` разбирается без `unresolved_import`, если зависимости в Maven-кеше.

### I — Граф зависимостей проекта — TODO

- [ ] По всем файлам проекта построить граф: пакеты и классы как узлы, `import` и вызовы методов как рёбра.
- [ ] Визуализировать в отдельном представлении (не CFG-viewer) с layout ELK.
- [ ] Выделить strongly connected components (циклические зависимости) — диагностика `circular_dependency`.
- [ ] Клик по классу → открыть его файл в редакторе.
- [ ] Фильтры: показывать только пакет, только внешние зависимости, только цикличные.
- [ ] Приёмка: граф Commons Math содержит ≥ 300 классов; циклические зависимости совпадают с `jdeps`.

### J — Рефакторинг с пересборкой и тестами — TODO

Это финальный слой; зависит от F, G, H, I.

- [ ] Рефакторинг применяется к рабочей копии проекта (не к оригиналу).
- [ ] Для изменения нескольких файлов — единый diff по всем затронутым файлам.
- [ ] После применения запускается `mvn compile` (или `gradle build`) на рабочей копии.
- [ ] Затем запускаются тесты: `mvn test -pl <module> -Dtest=<selected>`.
- [ ] Результат тестов показывается в UI с разбивкой passed/failed/error.
- [ ] Изменение можно отменить одной кнопкой (восстановить рабочую копию из оригинала).
- [ ] Приёмка: Extract method на компоненте Commons Math → `mvn test` проходит для выбранных тестов.
